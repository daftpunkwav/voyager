# AGENTS.md — 文档规范

本文件定义 `docs/` 的目录结构、双语配对契约与写作规则。文档放置问题从[索引](README.zh.md)开始。

## 文档结构

文档按类别目录组织:

| 路径 | 类别 | 内容 |
|---|---|---|
| `docs/` 根 | 总览 | [索引](README.zh.md)、[架构](architecture.zh.md)、[开发](development.zh.md)、[测试](testing.zh.md) |
| `subsystems/` | 子系统参考 | 每个后端子系统或域一页:定义、类型、端点、存储与事件。索引见 [subsystems/README.md](subsystems/README.zh.md) |
| `catalog/` | 目录型参考 | 生成面式清单:agent 工具面([tool-catalog](catalog/tool-catalog.zh.md))、注册的设置键([config-catalog](catalog/config-catalog.zh.md))、运行时数据布局([data-layout](catalog/data-layout.zh.md)) |
| `web/` | 前端参考 | 浏览器应用:[frontend](web/frontend.zh.md) |
| `i18n/` | 翻译流程 | [配对契约](i18n/README.zh.md) |

文档的主题与树位置决定其范围:描述所属子系统的类型、语义、端点与存储;对同级子系统只描述交互面,细节链接到所属页面。测试机制归 [testing.md](testing.zh.md),上层文档链接到那里。

## 双语配对

本树下每篇文档以三件一组维护:

- `foo.md` — 英文源。
- `foo.zh.md` — 中文对应版。
- `foo.i18n.yaml` — 一致性记录,保存两侧最近一次确认一致时的 git blob 哈希。

两种语言具有同等权威;配对双方必须表达相同内容。规则:

- 中文文件在 H1 之后立即回链:`[English](foo.md) | 中文`。英文文件对等:`English | [中文](foo.zh.md)`。
- 结构与对应版镜像:标题深度与顺序、列表类型、表格行列数、逐字代码块一一对应。双语文档之间的相对链接使用目标侧语言(`foo.zh.md` 链到 `bar.zh.md`);指向源码的链接保留真实路径。
- 修改任一侧后,同一变更内更新对应版,然后用 `git hash-object <file>` 重新记录两侧哈希(见[配对契约](i18n/README.zh.md))。

## 写作规则

- **描述当前状态,不写变更历史。** 指名现有机制,不写 commit、PR 或"以前/现在"。陈述当前事实。
- **面向代码。** 每个非显而易见的断言都有路径、类型名、端点或设置键支撑。引用代码用相对仓库根的 `path/to/file.py`;上下文明确时可用相对子系统文档的 `module.py`。
- **中立、可验证。** 描述代码实际行为,包括限制与失败行为。不陈述未验证的行为;事实无法在源码中确认时,直接省略而非猜测。
- **每段一行。** 使用编辑器软换行。代码块、表格与列表结构保留原格式。
- **不复述目录。** 源码或生成器为权威之处(工具名、设置键、端点),目录文档做摘要并链接到声明模块;不在多个位置手工照抄。每个事实只有一个家;其他地方链接过去。
- **直接书写。** 指名执行者、文件与事实。避免比喻性的承重词;说出确切的类型、API 或操作。
- **不写实现状态标注。** "计划中"、"TODO"、"未来"不属于这些文档;仓库布局与 issue 跟踪承载状态。

## 反冗余清单

在任何文档中排查:

- 同一规则在多个位置陈述。用特征短语 grep;保留一个家,其余链接。
- 历史叙述:"以前"、"现在"、"不再"、"改名"。陈述当前事实。
- 源码为权威时手工照抄测试、包或键的清单。
- 推理记录:实现过程叙述、显而易见分支的论证、被否决的备选方案。保留结果契约,删除推导路径。
- 强调膨胀:到处加粗或大写等于没有重点。
- 段落墙:一个段落装多条规则与插入语。拆开。
